build-time-only (they cannot reflect per-workspace dynamic branding data

"Based on my review of the live app and source, here's where I see room for
improvement — roughly prioritized.

Command Centre is showing false, Phase-1-era placeholder copy. The stat
cards for 'Active ventures,' 'Pending approvals,' and 'Budget utilisation'
still carry Phase 2+ / Phase 3+ / Phase 7 badges, and the 'What's real vs.
planned' card literally says opportunity research, the AI board, approvals,
product studios, and finance dashboards 'are architected... but not yet
built.' All 8 phases are actually complete and shipped. This is the first
page anyone sees after logging in, so right now it's actively telling
founders and customers the product is far less finished than it is.
Highest-priority fix.

White-label branding doesn't reach the browser tab. WorkspaceBranding
(name/logo/accent color) correctly cascades to the sidebar and buttons, but
apps/web/src/app/layout.tsx has a hardcoded static metadata object (title:
'VentureOS'). A fully rebranded workspace still shows 'VentureOS' in the
browser tab and any social/link previews — undermining the point of the
white-label feature. Fix requires converting to generateMetadata() so it can
read the per-workspace branding server-side.

Duplicate nav destination. In dashboard-nav.tsx, 'Product Studio' and 'Board
Room' both point to /dashboard/board-room — two adjacent sidebar links go to
the exact same page, which reads as a bug.

No active-page indicator in the sidebar. DashboardNav is a static map with
no usePathname() check, so nothing highlights which page you're currently
on — easy to lose your place, especially with 12 nav items.

Stale badge on a permanently-deferred item. 'Workflow Centre' is disabled
with a 'Phase 2+' badge and 'planned for a later phase' tooltip, but per the
Phase 7 closeout this was intentionally deferred for good (Board Room/
Approval Centre cover the need), not 'coming later.' The copy should say
something like 'Not planned' rather than implying it's still on the roadmap.

Smaller polish items, worth a pass but lower priority: destructive actions
(Cancel subscription, Revoke license key) aren't visually distinguished from
safe ones (Change plan, Issue key) — no red/warning styling or confirm step;
native <select> dropdowns look inconsistent against the custom-styled dark
inputs elsewhere; several fixed-pixel widths (sidebar 220px, auth cards
380px) may not degrade well on narrow viewports (I wasn't able to confirm
this live — window resize didn't visibly take effect in my browser session,
so treat this as a code-level observation, not a confirmed visual bug); some
empty states are plain text where a direct link to the relevant action (e.g.
'no proposals yet' linking straight to the Opportunity Feed) would reduce
clicks; and the Audit Centre's 'Correlation ID' column shows '–' on every
row, which might indicate an under-populated field worth double-checking
rather than an intentional design choice.

Want me to implement any of these? The Command Centre copy/badges and the
duplicate nav link are quick, low-risk fixes if you want to start there."
