# Threat Model

Status legend: **Mitigated** (control exists in code) · **Partially
mitigated** · **Not yet addressed** (planned for a specific phase).

| Threat                                       | Status                                | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prompt injection / indirect prompt injection | Mitigated (Phase 5)                   | `sanitizeUntrustedContent` (`packages/research-connectors/src/prompt-injection-sanitizer.ts`) runs on every raw acquisition payload before it is persisted as `EvidenceArtifact.originalExcerpt` or could reach any agent prompt. Proven with real test evidence: unit tests (`prompt-injection-sanitizer.test.ts`) and an integration test that persists a poisoned mock payload and asserts the dangerous instruction text never appears in the actual DB row (`research-connectors.integration.spec.ts`, "SECURITY: neutralizes prompt-injection content..."). This is pattern-based detection, not a formal guarantee — novel phrasings can still evade it, so acquired content must still always be treated as untrusted data, never as instructions, regardless of sanitiser output |
| Malicious/poisoned research source           | Mitigated (Phase 5)                   | `DataAcquisitionContract.disabled` kill switch (fail-closed, checked before every run), per-contract rate limits, per-run/per-workspace-day cost caps, and source-type-based reliability scoring that further penalises any source whose payload gets flagged by the prompt-injection sanitiser (`computeReliabilityScore` in `evidence-scoring.ts`) — a poisoned source is scored as less trustworthy, never silently trusted at full confidence. Real DB proof in `research-connectors.integration.spec.ts`                                                                                                                                                                                                                                                                             |
| Secret leakage (logs)                        | Mitigated                             | `redactSecrets` on every structured log line                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Secret leakage (source/docs)                 | Mitigated                             | `.env.example` only, `.gitignore` excludes `.env`, grep-checked before commit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Excessive agent tool permissions             | Partially mitigated                   | `AgentDefinition.toolAllowlist`/`prohibitedActions` defined and seeded per role since Phase 3, but no runtime layer yet enforces an actual tool call against its role's allowlist -- still a real gap, not just a placeholder (note corrected from a stale Phase 1 reference to "no agent runtime yet")                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Approval bypass                              | Partially mitigated                   | Deterministic approval/hash/founder checks exist. Approval decisions use a conditional single-writer state transition in the same transaction as decision evidence. SCALE approvals bind the current proposal version plus the exact experiment definition, metrics, variants, and results; decision and execution both reject expired, version-mismatched, or hash-drifted evidence. Live publication/spend adapters remain unavailable and require separate validation before connection                                                                                                                                                                                                                                                                                                |
| Hash mismatch (approved artefact changed)    | Mitigated (mechanism)                 | Kind-specific canonical hashing binds the artifact actually being approved: proposal snapshots, product/listing packages, publication content, or proposal-plus-experiment evidence for SCALE                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Duplicate external execution                 | Mitigated for mock adapter            | `withIdempotency` wraps every mock marketplace write. Matching successful replays do not re-execute the adapter and are revalidated against current tenant-bound policy/local state before creating a new success record; conflicting payloads fail and failed keys retry in place. Scope remains the mock adapter; live-provider idempotency and compensation require separate validation                                                                                                                                                                                                                                                                                                                                                                                                |
| Cross-workspace data exposure                | Partially mitigated                   | Sensitive queries generally use the server-derived workspace. Phase 10 fixed tenant exposure of unscoped global security events and bound experiment variant/metric/result IDs to one route experiment; continued query-by-query isolation tests remain required                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Malicious file upload                        | Mitigated                             | MIME allowlist, size limit, path-traversal rejection                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Path traversal                               | Mitigated                             | Object-key validation in storage provider                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| SQL injection                                | Mitigated                             | Prisma parameterized APIs are used. Tagged, parameterized raw SQL is also used for bounded health, authentication-abuse, and quota-serialization controls; no unsafe concatenating raw-query API was found in the reviewed paths                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Cross-site scripting                         | Partially mitigated                   | React auto-escapes; no `dangerouslySetInnerHTML` anywhere in Phase 1 code                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Cross-site request forgery                   | Mitigated (application)               | Global `CsrfOriginGuard` rejects authenticated unsafe methods unless `Origin` exactly matches `API_CORS_ORIGIN`; safe methods and cookie-less public auth requests are intentionally exempt. `sameSite=lax` and the CORS allowlist remain defense in depth                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Session theft                                | Partially mitigated                   | httpOnly/secure/sameSite cookie; only deterministic SHA-256 token digests are persisted and incoming raw tokens are digested before lookup. MFA, account recovery, device/session management, and production transport/deployment controls remain deferred                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Brute-force login                            | Mitigated (Phase 11)                  | PostgreSQL-backed normalized account and source-IP cooldowns are shared across API processes and survive restarts. Keys and security-event metadata contain only domain-separated keyed digests. Missing accounts execute the same scrypt verification on libuv's worker pool; already-blocked requests skip the KDF. Forwarded addresses are ignored unless a bounded `API_TRUST_PROXY_HOPS` value explicitly enables proxy trust. Registration has source-wide durable limiting, generic `202` responses, duplicate-email handling, bounded transactional workspace-slug retries, and a bounded response-time floor. The global Nest limiter remains defense in depth, not the durable enforcement layer                                                                                |
| Dependency compromise                        | Mitigated for validated lockfile      | Compatibility-tested dependency remediation reduced production and complete audits to zero findings for the validated lockfile. This is not a permanent waiver: frozen install and recurring audits remain required whenever the lockfile changes; see `APPLICATION_SECURITY_BASELINE.md`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Audit-log tampering                          | Partially mitigated                   | Versioned per-event integrity checksums, workspace/source replay keys, and a DB trigger reject immutable-content updates. Nullable actor/workspace relations may only clear during erasure, and explicit deletion remains available for governed retention/erasure. This is not a signature, hash chain, external transparency log, or protection from an administrator who can rewrite both content and checksum. Temporal workflow coverage remains provided by `apps/worker/src/lib/write-audit-event.ts` (ADR-008); the provider-neutral ACP event envelope and persistence mapping are documented in ADR-0018.                                                                                                                                                                       |
| Destructive commands                         | Mitigated (Phase 1 scope)             | No destructive endpoints exist yet; soft-delete columns present on `User`/`Workspace`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Unbounded AI cost                            | Not yet addressed                     | Env vars for limits exist (`AI_PER_*_COST_LIMIT_EUR`); no agent runtime to enforce them yet. The analogous research-spend concern is now real (Phase 5): `assertWithinResearchCostCaps` enforces a per-run and per-workspace-per-day cap, integration-tested (`BLOCKED_COST_CAP`) -- the same pattern, applied so far only to research runs, not yet to agent/model calls                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Denial of service                            | Partially mitigated                   | General and shared durable authentication limits exist. Public Temporal health performs only a bounded gRPC Health `Check`, creates no workflow history, and returns generic status. Authentication transaction admission and Playwright login synchronization were subsequently stabilized and regression-tested. Broader deployment capacity, worker/task-queue readiness, and staging controls remain open                                                                                                                                                                                                                                                                                                                                                                             |
| Known bootstrap credential                   | Mitigated (Phase 10)                  | Fixture seeding requires explicit non-placeholder founder credentials and refuses production; the repository-known fallback can no longer create a privileged account                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Subscription/provider gate bypass            | Mitigated for current paths           | Central policy enforces subscription status, trial expiry, active plan, entitlement, quota, required provider configuration, and global switches at admission plus queued/direct/final boundaries. Research and every mock marketplace adapter call immediately revalidate current tenant-bound local state and policy; MinIO checks before network I/O; worker denials are non-retryable. This is best-effort TOCTOU narrowing rather than a transactional lease. Live commercial adapters remain absent and must preserve non-bypassable final checks when introduced                                                                                                                                                                                                                   |
| Container escape                             | N/A to current application deployment | Disposable PostgreSQL was used for local validation, but no VentureOS application image or production container deployment was built or assessed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Insecure backup / retention failure          | Not yet addressed                     | Phase 1 has no backup automation; `docs/BACKUP_AND_RECOVERY.md` documents the intended procedure                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

This table will be re-scored at the end of every phase.
